# INVESTOR SECTION

## What's Been Built

As of 2026-03-03, Ops OS has a working prototype available at https://ops-os-gamma.vercel.app that a capital markets operations user can sign in to and use today:

- **Block management:** Create and browse stateful business entities (clients, deals, counterparties) with a full event timeline for each — immutable audit log from day one.
- **Workflow automation:** Trigger multi-step operational workflows (e.g. client onboarding) through a single action. The system queues and executes workflow steps automatically, with full status visibility in a dedicated Workflows page.
- **AI chat assistant:** Ask questions about any block or your organisation in plain English. The AI draws on both recent events and semantically relevant historical context to answer — it knows what's happened, not just what's been typed at it.
- **Role-based access control:** Three roles enforced at the API level — ops-admin, ops-user, and compliance-approver. Compliance approvers cannot create blocks or trigger actions — read-only by design.
- **Real-time dashboard:** Metrics (block counts by type, active workflows, events in last 24h) with a live event feed and one-click block creation.

## Infrastructure and Scalability

The current deployment (Vercel + Supabase free tier, ap-south-1 / Mumbai region) can handle early design partner usage without modification. The workflow engine uses Postgres-level locking, meaning horizontal scaling of the processing cycle is safe — two instances will not double-process the same job. The system would need a Temporal migration and Neon Postgres before handling 50+ concurrent organisations with heavy workflow volumes; that is Phase 4 scope and is explicitly planned. At 2–5 design partner organisations with 10–50 workflows/week, the current infrastructure has meaningful headroom.

## Current Honest Limitations

1. **Workflow types are hardcoded.** Only `onboarding` workflow exists. A new workflow type requires a code deployment. Workflow configurability (templates, jurisdiction overrides) is Phase 2.

2. **No real design partners yet.** The system has never been used by an external user. DE-01 (design partner onboarding) is in progress. Phase 1 exit conditions require 2 orgs with 10+ workflow jobs/week — that evidence does not yet exist.

3. **Postgres job queue is not production-grade.** FOR UPDATE SKIP LOCKED is sound at this scale, but there is a known bug: if Supabase returns a DB error during job completion, the job stays stuck in `running` state and is never retried. Acceptable at prototype scale with rare DB errors.

4. **Single-region deployment.** Production is ap-south-1 (Mumbai/India) — chosen because the primary design partner market is Australia (ASIC). Multi-region (FCA/MAS/ASIC) is Phase 4. Data residency requirements of non-Australian design partners are not currently met.

5. **No workflow configuration UI.** Users cannot create or modify workflow definitions without engineering involvement. This is a Phase 2 feature.

6. **RBAC is basic.** Three roles are enforced, but there is no UI for assigning roles — user_roles rows must be inserted directly into Supabase. Admin UI for role management is not scoped until Phase 2.
